# Jules task — timestamped shared resource-lease revocation

This disposable repository contains one task only. Its `main` branch must be the exact authoritative Engine PR #47 tree plus this workbench manifest/task commit. Do not infer scope from the repository’s historical default branch.

## Objective

Repair `packages/background-service-runtime` so background lease holders can observe the earliest live foreground request as a typed, timestamped revocation event and can wait for revocation without repeatedly materializing an unbounded request set.

The downstream consumer is Evidence Service issue #21, which owns a two-second end-to-end policy. Do **not** place that policy in the shared package.

## Required contract

Add one provider-neutral revocation observation containing at least:

- `revoked` boolean;
- bounded reason code for no revocation, holder release, holder identity loss, and foreground demand;
- bounded foreground producer when applicable;
- request nonce/identity and priority;
- original request visibility timestamp as canonical UTC text and safe-integer Unix milliseconds;
- observation timestamp as canonical UTC text and safe-integer Unix milliseconds.

Select the earliest valid live foreground request deterministically. Foreground request heartbeats must preserve the original request timestamp.

Malformed, missing, or ambiguous request timestamps must never be converted into a later deadline. Future timestamps must be handled conservatively and must not produce negative elapsed time for consumers.

Retain a compatibility `revocationReason()` projection if needed, but make the typed observation the authority.

Provide an abortable asynchronous wait API with a bounded poll fallback. It must clean up timers/watchers on success, cancellation, release, identity loss, and exceptions. Notification failure must not lose the earliest request timestamp.

## Bounds and safety

- Bound request packet bytes, producer length, request count, and diagnostic text.
- Do not expose private lease-directory paths in the public observation.
- Do not require high-frequency full-directory arrays.
- Preserve exact holder/request identity and stale cleanup behavior.
- Preserve Windows and Linux operation.
- Do not import Evidence Service or any provider source.

## Validation

Use the production implementation and cover:

- no revocation;
- holder release and identity replacement;
- one foreground request;
- multiple foreground requests with deterministic earliest selection;
- request heartbeat preserving original visibility time;
- malformed, missing, stale, and future request timestamps;
- request arriving immediately after observation;
- asynchronous wakeup and bounded poll fallback;
- aborted wait and no leaked timers/watchers;
- maximum request-set bounds and scan/allocation behavior;
- compatibility `revocationReason()` behavior;
- Windows and Linux filesystem behavior.
