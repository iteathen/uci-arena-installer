# Fresh provider configuration handoff

An installed Vector generated profile correctly contains the selected Book snapshot binding and pinned timing policy, but consumers currently bind only the immutable factory launch profile. Consequently an apparently verified installation can drop valid operator knowledge selection. A temporary owner-authorized operator composition has restored actual Bot operation; it is not the durable Installer repair.

The cause concerns C05/C08/C09/C10/C11, Installer objectives I-O1/I-O2 and suite objectives G-O1/G-O2. Independently released components own their configuration semantics; Installer owns exact composition and transactional deployment. A correct local profile is insufficient when the public consumer handoff loses that profile. Targets for usable composition, independent ownership, truthful evidence, preservation and provenance constrain this decision. Security and exact component authority are hard gates; neither usability nor engineering convenience overrides them. Conditional precedence is limited to rejecting a composition that loses the selected producer-owned behavior.

Candidates: teach Installer Book/UCI/timing semantics (inadmissible ownership violation); copy selected options independently into every consumer (rejected duplicate engine authority); bind the producer's stored generated file (rejected because it can be stale during locator/update transactions); forward fresh output from the verified producer public renderer, with dependent refresh and one render snapshot per transaction (selected). The generic binding is useful for any component-owned configuration; component identity never selects its mechanism.

`source: configuration` is an additive declared dependency binding. It returns the producer's current configuration object using its receipt-selected managed component, validated full payload, exact owned version root, declared workspace, current dependency paths and saved locators. Windows uses existing descriptor-bound exact receipt admission and bounded duplicate-rejecting JSON. The current Linux receipt adapter remains bounded/path based, and this change does not claim Windows physical-admission guarantees on Linux. Absent optional dependencies are omitted; present invalid authority fails rather than silently falling back.

Cycles, depth beyond sixteen, more than sixty-four renderer calls and contexts over one MiB fail before consumer activation. Locator refresh selects the transitive configuration-consumer closure independent of receipt order. Memoized component/root/workspace/enabled outputs give consumers and producer-owned documents the same render snapshot. Existing write/rollback and startup/publication/provenance gates remain intact. No producer state, credential contents, engine semantics or release assets are interpreted by Installer.

TDD retained two initial failures: stale-file handoff and cyclic projection. Both pass after the binding repair. An additional transitive locator regression failed when only the producer matched the locator kind; it passes after dependency closure/memoization. Optional absence versus corrupted present inventory and rollback preservation have a dedicated regression. Native full-suite qualification and nonauthor review are required at the final source; consumer adoption, signed packaging, installed update/verify and real service-product acceptance remain separate steps. This source does not claim complete product repair.

The first nonauthor review found two substantive omissions: lexical producer roots could redirect through a link, and invalid transitive-only producer payloads could disappear from refresh selection. The first revision was rejected. Producer admission now rejects linked roots/ancestors and holds a Windows native directory admission through projection with final object/path checks. A verified configuration consumer of a present unusable producer is conservatively selected for failing projection: the invalid payload cannot establish locator relevance, and no locator commits with stale dependent output. The transitive corruption regression reproduced a failure before this repair and now preserves both old configurations and absent saved authority on rejection.

At the repaired revision the Windows native suite passed 3,716 assertions in 226 cases, with five explicit symbolic-link capability skips (Win32 1314). Focused configuration coverage passed 39 assertions in four cases with one of those link skips. The link regression remains runnable on capable hosts; this local result does not claim it executed. Exact revised bytes require renewed independent review before integration. These checks qualify source behavior, not a signed Installer release or completed deployed composition.
